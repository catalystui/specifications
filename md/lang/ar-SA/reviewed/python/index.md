# تفاصيل المراجعة

## Python

### نظرة عامة

تمت مراجعة لغة البرمجة Python مقابل مواصفتي FDEFSPEC (Rev. 1) و FRELSPEC (Rev. 1) اعتبارًا من 7 يوليو 2026.

#### بيان المراجعة

مع أن Python تستطيع تمثيل كثير من المفاهيم المطلوبة من خلال الأنواع المدمجة والكائنات والدوال والأصناف ووحدات المكتبة القياسية والتحقق المخصص، فإن هذه الآليات ليست كافية لتلبية مواصفات CatalystUI المطبقة على مستوى اللغة.

توفر Python دعمًا قويًا لترميز النص والملفات والتدفقات والكائنات والدوال والأصناف والخصائص والعمليات والخيوط التنفيذية والتنفيذ الموزع من خلال سلوكها المدمج ومكتبتها القياسية. ومع ذلك، لا توفر Python أنواع الأعداد القياسية ذات العرض الثابت المطلوبة، ولا تعرّف ثوابت حقيقية، وتعتمد على سلوك ديناميكي في وقت التشغيل لعدة بُنى تستطيع اللغات المعتمدة الأخرى التعبير عنها بشكل مباشر أكثر.

وبسبب ذلك، لا نعتقد أن Python توفر أساسًا مستقرًا بما يكفي لتنفيذ متوافق مع CatalystUI دون بنية إضافية كبيرة.

ونتيجة لذلك، لم تُمنح Python حالة الاعتماد من CatalystUI للغات البرمجة.

#### افتراضات المراجعة

تقيّم هذه المراجعة Python نفسها ومكتبتها القياسية المرفقة.

لا تُعامل الحزم الخارجية، والامتدادات الخاصة بالتنفيذ، والوحدات الأصلية الاختيارية، وأدوات فحص الأنواع الخارجية، والمحوّلات البرمجية، وأطر وقت التشغيل المخصصة على أنها دعم على مستوى اللغة.

### التحذيرات

* توفر Python أعدادًا صحيحة غير محدودة الدقة، لا بدائيات أعداد صحيحة ذات عرض ثابت.
* عادةً ما يكون `float` في Python مزدوج الدقة، لكنه ليس عائلة مميزة ذات عرض ثابت.
* قد يتطلب بعض سلوك الذاكرة منخفض المستوى `ctypes` أو سلوكًا خاصًا بالتنفيذ.
* لا تُفرض تلميحات الأنواع في Python وقت التشغيل.
* تدعم Python الخصائص، لكن قد يُحذف سلوك setter.
* تستطيع Python نمذجة عدة بنى من خلال ميزات المكتبة القياسية، لكن ليس كنوع بنية أصلي.

### الإخفاقات

* لا توفر Python معظم أنواع الأعداد القياسية ذات العرض الثابت المطلوبة.
* لا توفر Python نوعًا قياسيًا مخصصًا للفاصلة العائمة من 32 بت.
* لا توفر Python ثوابت حقيقية على مستوى اللغة.
* لا تعرّف Python الإجراءات منفصلة عن الدوال.
* لا توفر Python دعمًا أصليًا للمؤشرات.
* لا توفر Python دعمًا أصليًا للواجهات.
