<a id="introduction"></a>
## Введение

**Internationalization Specification (I18NSPEC)** устанавливает основные понятия, терминологию и требования, используемые для оценки многоязычной поддержки в экосистеме CatalystUI. Ее цель — предоставить ясный стандарт для определения того, обеспечивает ли система, сервис, framework, приложение или реализация достаточную языковую поддержку, чтобы считаться соответствующей спецификации.

Интернационализация важна потому, что пользовательский интерфейс не может ясно общаться, если его существенный смысл доступен только на одном языке. Система может быть технически работоспособной, но если пользователи не понимают ее метки, инструкции, элементы управления, настройки, предупреждения, ошибки или основные рабочие процессы, то система не предоставила этим пользователям осмысленный интерфейс.

Эта спецификация не пытается измерять идеальное качество перевода, литературный стиль, культурную адаптацию, юридическое соответствие или полную региональную локализацию. Вместо этого она определяет минимальную многоязычную основу, необходимую для того, чтобы пользователи могли осмысленно получать доступ к существенным частям системы и использовать их во всем требуемом наборе locale CatalystUI.

Проще говоря, I18NSPEC задает три основных вопроса:

1. Могут ли пользователи получить доступ к существенным частям системы на каждом требуемом языке?
2. Могут ли пользователи разумно выбрать язык, который они понимают?
3. Сохраняет ли система достаточно смысла между языками, чтобы оставаться пригодной к использованию?

> [!IMPORTANT]
>
> I18NSPEC определяет требования интернационализации для проверки. Это не отдельная спецификация для каждого языка. Каждый требуемый locale проверяется по одной и той же спецификации.

<a id="conformance"></a>
## Соответствие

Система считается соответствующей I18NSPEC, когда она удовлетворяет требованиям, определенным этим документом, для каждого locale в требуемом наборе locale.

Соответствующая система должна:

1. Поддерживать каждый locale из требуемого набора locale.
2. Предоставлять переведенный контент для более чем 75% существенного пользовательского контента в каждом требуемом locale.
3. Предоставлять переведенный контент для всего критического пользовательского контента в каждом требуемом locale.
4. Предоставлять разумный механизм для конечного пользователя, позволяющий выбрать активный locale.
5. Использовать стабильный механизм перевода, подходящий для системы.
6. Сохранять существенный смысл переведенного пользовательского контента.
7. Не полагаться на fallback-контент для заявления о покрытии переводом, кроме случаев, когда эквивалентность locale принята во время review.

Системе не нужно использовать один конкретный шаблон реализации, чтобы соответствовать этой спецификации. Она может использовать resource-файлы, таблицы переводов, маршрутизацию с учетом locale, скомпилированные языковые ресурсы, статические локализованные страницы, языковые пакеты времени выполнения, переводы на основе базы данных или другой стабильный механизм, подходящий для системы.

Проверка касается практического доступа пользователя и существенного смысла, а не одной жесткой технической архитектуры.

<a id="user-facing-content"></a>
## Пользовательский контент

<a id="user-facing-content-1"></a>
### Пользовательский контент

Пользовательский контент — это любой контент, предназначенный для восприятия, чтения, прослушивания, выбора, понимания или действия со стороны конечного пользователя.

Пользовательский контент может включать:

* навигацию
* метки
* кнопки
* меню
* элементы управления
* заголовки
* диалоги
* настройки
* инструкции
* prompts
* предупреждения
* ошибки
* подтверждения
* сообщения о состоянии
* текст первичного знакомства
* обязательный справочный текст
* элементы выбора языка
* контент основных рабочих процессов

Пользовательский контент не обязан быть визуальным. Он также может включать аудиальный, тактильный, символический или мультисенсорный контент, когда этот контент сообщает пользователю смысл.

<a id="essential-user-facing-content"></a>
### Существенный пользовательский контент

Существенный пользовательский контент — это пользовательский контент, который пользователю разумно необходим, чтобы понять, навигировать, настроить или использовать существенное поведение системы.

Существенный пользовательский контент может включать:

* основную навигацию
* основные экраны и представления
* настройки и предпочтения
* пользовательские метки
* пользовательские элементы управления
* обязательные инструкции
* важные предупреждения
* важные ошибки
* существенные prompts
* обязательные сообщения подтверждения
* элементы выбора языка
* основные рабочие процессы, необходимые для обычного использования

Системе не нужно переводить каждую необязательную страницу, скрытое сообщение, внутреннюю метку или несущественный текст, чтобы удовлетворять I18NSPEC. Однако контент, необходимый для обычного существенного использования, должен быть переведен согласно требованиям этой спецификации.

<a id="critical-user-facing-content"></a>
### Критический пользовательский контент

Критический пользовательский контент — это существенный пользовательский контент, где непонимание может помешать осмысленному использованию, создать серьезную ошибку или привести пользователя к важному решению без понимания последствия.

Критический пользовательский контент может включать:

* элементы выбора языка
* предупреждения о разрушительных действиях
* предупреждения об удалении учетной записи
* подтверждения оплаты
* подтверждения покупки
* выборы конфиденциальности
* предупреждения безопасности
* prompts согласия
* обязательные инструкции безопасности
* обязательные инструкции настройки
* обязательные сообщения об ошибках
* основную навигацию, необходимую для перехода к языковым настройкам

Критический пользовательский контент должен быть переведен для каждого требуемого locale.

Порог 75% существенного покрытия переводом не должен использоваться для оставления критического контента без перевода.

<a id="nonessential-content"></a>
### Несущественный контент

Несущественный контент — это контент, который не является разумно необходимым для того, чтобы пользователь понял, навигировал, настроил или использовал существенное поведение системы.

Несущественный контент может включать:

* внутренние идентификаторы
* имена исходного кода
* строки только для отладки
* детали реализации, предназначенные для разработчиков
* скрытый диагностический текст
* необязательные маркетинговые страницы
* необязательные страницы поддержки
* несущественный юридический или деловой текст вне рассматриваемой области
* сторонний контент, не контролируемый рассматриваемой системой

Несущественный контент может быть переведен, но это не требуется для соответствия I18NSPEC, если он не становится необходимым для существенного понимания или использования пользователем.

<a id="translation-coverage"></a>
## Покрытие переводом

<a id="essential-translation-coverage"></a>
### Существенное покрытие переводом

Существенное покрытие переводом — это объем существенного пользовательского контента, переведенного для конкретного locale.

Покрытие следует оценивать по осмысленным единицам пользовательского контента, а не по размеру файла, количеству байтов, количеству строк, размеру репозитория или числу страниц.

Например, одна непереведенная кнопка, управляющая существенным действием, может иметь большее значение, чем большой непереведенный необязательный абзац, который не влияет на обычное использование.

Покрытие переводом следует оценивать по тому, может ли пользователь осмысленно понять и использовать существенную систему в рассматриваемом locale.

<a id="coverage-requirement"></a>
### Требование к покрытию

Система удовлетворяет требованию к покрытию переводом для locale, когда более 75% существенного пользовательского контента переведено для этого locale.

Система удовлетворяет требованию покрытия I18NSPEC, когда она достигает этого порога для каждого locale в требуемом наборе locale.

В практическом review это может быть представлено так:

| Locale  | Существенное покрытие переводом | Результат |
| ------- | -------------------------------- | --------- |
| `en-US` | 100%                             | Pass      |
| `es-ES` | 94%                              | Pass      |
| `ar-SA` | 78%                              | Pass      |
| `ja-JP` | 61%                              | Fail      |

Locale с покрытием 75% или меньше не удовлетворяет требованию к покрытию.

Locale с покрытием более 75% все равно может не пройти, если критический пользовательский контент не переведен.

<a id="critical-content-requirement"></a>
### Требование к критическому контенту

Весь критический пользовательский контент должен быть переведен для каждого требуемого locale.

Система может не пройти I18NSPEC даже при выполнении общего порога покрытия, если один или несколько элементов критического пользовательского контента отсутствуют, не переведены, вводят в заблуждение или не являются осмысленно понятными.

Например, система не должна считаться находящейся в рамках спецификации, если общий интерфейс переведен, но предупреждение об удалении учетной записи, подтверждение покупки, предупреждение безопасности или селектор языка остаются непереведенными.

<a id="language-selection"></a>
## Выбор языка

<a id="active-locale"></a>
### Активный locale

Активный locale — это locale, выбранный в данный момент для пользовательского опыта.

Активный locale определяет, какой переведенный контент должен отображаться, предоставляться или иным образом сообщаться пользователю.

<a id="default-locale"></a>
### Locale по умолчанию

Locale по умолчанию — это locale, используемый, когда пользователь не выбрал активный locale или когда пользовательская предпочтительная настройка недоступна.

Система должна определить locale по умолчанию.

Locale по умолчанию должен быть задокументирован или разумно выводим рецензентом.

<a id="language-selection-mechanism"></a>
### Механизм выбора языка

Соответствующая система должна предоставить разумный способ для конечного пользователя изменить активный locale.

Механизм выбора языка должен быть доступен без требования к пользователю:

* изменять исходный код
* использовать инструменты разработчика
* редактировать незадокументированные конфигурационные файлы
* устанавливать неофициальные patches
* полагаться на скрытое поведение
* обращаться в поддержку для обычных изменений языка

Механизм выбора языка может предоставляться через:

* настройки приложения
* предпочтения учетной записи
* селектор языка
* prompt при запуске
* настройки браузера
* настройки операционной системы
* настройки устройства
* другой подходящий механизм, доступный конечному пользователю

Механизм не обязан следовать одному конкретному шаблону дизайна. Он должен разумно позволять пользователю выбрать поддерживаемый язык.

<a id="language-option-labels"></a>
### Подписи вариантов языка

При отображении вариантов языка система должна идентифицировать каждый язык способом, понятным пользователям, которые говорят на этом языке.

Вариант языка может включать:

* название языка на этом языке
* название языка на текущем активном языке
* код locale
* региональную подпись
* подпись письменности

Например:

```md
English (English) (en-US)
Español (Spanish) (es-ES)
Français (French) (fr-FR)
العربية (Arabic) (ar-SA)
```

Точное форматирование может различаться.

Смысл в том, чтобы пользователи могли распознать свой язык, по возможности понять отображаемое название языка и определить связанный код locale.

<a id="fallbacks-and-locale-equivalence"></a>
## Fallback и эквивалентность locale

<a id="fallback-locale"></a>
### Fallback-locale

Fallback-locale — это locale, используемый, когда переведенный контент недоступен для активного locale.

Fallback-locale может помогать сохранять пригодность к использованию, но fallback-контент автоматически не считается переведенным контентом для активного locale.

Например, если система настроена на `es-MX`, но отображает текст `en-US`, потому что испанский перевод отсутствует, этот английский текст может быть полезен как fallback, но он не должен учитываться как покрытие испанским переводом.

<a id="fallback-behavior"></a>
### Поведение fallback

Соответствующая система может использовать fallback-поведение, когда локализованный контент недоступен.

Fallback-поведение должно избегать сломанного, пустого или вводящего в заблуждение вывода.

Fallback-поведение не должно использоваться для ложного заявления о покрытии переводом для требуемого locale.

Система может получить предупреждение или ошибку соответствия, если fallback-поведение чрезмерно, запутанно, незадокументировано или приводит к тому, что существенный контент выглядит непереведенным в требуемом locale.

<a id="locale-equivalence"></a>
### Эквивалентность locale

Эквивалентность locale возникает, когда один перевод может разумно обслуживать более одного locale, не мешая существенному пониманию или использованию.

Например, система может использовать один английский перевод для `en-US`, `en-GB` и `en-IN`, если существенный смысл остается ясным для пользователей каждого locale.

Эквивалентность locale может быть принята во время review, когда региональные различия незначительны и существенно не влияют на существенную пригодность к использованию.

Эквивалентность locale не должна использоваться, когда отсутствующий locale создаст значимую путаницу, опустит важную региональную терминологию, нарушит существенное поведение или помешает пользователям понять систему.

Например, система не должна предполагать, что несвязанные языки эквивалентны, потому что они имеют общее направление письма, географический регион, семейство письменности или широкую культурную категорию.

Эквивалентность locale — это суждение review, а не автоматическое правило.

<a id="implementation-requirements"></a>
## Требования к реализации

<a id="stable-translation-mechanism"></a>
### Стабильный механизм перевода

Соответствующая система должна использовать стабильный механизм перевода, подходящий для рассматриваемой системы.

Стабильный механизм перевода должен позволять поддерживать, обновлять, review-ить и расширять переведенный контент без опоры на хрупкое или незадокументированное поведение.

Стабильный механизм перевода может включать:

* resource-файлы
* таблицы переводов
* маршрутизацию с учетом locale
* скомпилированные языковые ресурсы
* статические локализованные страницы
* языковые пакеты времени выполнения
* переводы на основе базы данных
* другую задокументированную структуру перевода

Системе следует избегать жесткого кодирования существенного пользовательского контента таким образом, который препятствует требуемой поддержке перевода.

<a id="preservation-of-meaning"></a>
### Сохранение смысла

Перевод сохраняет смысл, когда пользователь может разумно понять ту же существенную инструкцию, метку, предупреждение, элемент управления, настройку или рабочий процесс, что и пользователи исходного языка.

Перевод не должен быть слово-в-слово идентичен исходному контенту.

Перевод может менять порядок слов, грамматику, структуру предложения, идиому, тон или формулировку, когда это необходимо для сообщения того же существенного смысла на целевом языке.

Перевод может не пройти review, если он вводит в заблуждение, неполон, бессмыслен, поврежден машинной обработкой или значимо отличается от исходного контента таким образом, который влияет на существенное использование.

<a id="direction-sensitive-languages"></a>
### Языки, чувствительные к направлению

Некоторые требуемые locale обычно используют направление текста справа налево.

Соответствующая система не должна препятствовать чтению, пониманию, выбору или действию на основании существенного переведенного контента из-за того, что активный locale использует другое направление текста.

Система должна сохранять читаемый порядок, поведение пунктуации и связь элементов управления для языков, чувствительных к направлению.

Полная визуальная полировка, качество типографики, поведение доступности и уточнение layout могут требовать отдельного review. Однако существенный переведенный контент должен оставаться осмысленно пригодным к использованию.

<a id="locale-sensitive-values"></a>
### Значения, чувствительные к locale

Значения, чувствительные к locale, — это значения, смысл или читаемость которых может различаться в зависимости от языка, региона, письменности или культуры.

Значения, чувствительные к locale, могут включать:

* даты
* время
* числа
* валюты
* измерения
* формы множественного числа
* грамматический род
* порядок сортировки
* форматы адресов
* форматы телефонных номеров

I18NSPEC не требует полной локализации каждого значения, чувствительного к locale, если это значение не является существенным для понимания или использования системы.

Когда значения, чувствительные к locale, являются существенными, система должна представлять их так, чтобы пользователи активного locale могли разумно их понять.

<a id="verification"></a>
## Проверка

<a id="within-spec"></a>
### В рамках спецификации

Система считается находящейся в рамках спецификации, когда команда CatalystUI рассмотрела систему и сочла разумным заключить, что она удовлетворяет I18NSPEC.

Система может находиться в рамках спецификации, когда:

* каждый требуемый locale поддерживается
* более 75% существенного пользовательского контента переведено для каждого требуемого locale
* весь критический пользовательский контент переведен для каждого требуемого locale
* пользователи могут разумно выбрать активный locale
* fallback-поведение не заявляет ложного покрытия переводом
* эквивалентность locale, если используется, разумна и задокументирована
* переведенный контент сохраняет существенный смысл

Система может находиться в рамках спецификации, даже если некоторый несущественный контент остается непереведенным.

Система может находиться в рамках спецификации, даже если переводы не идеальны, при условии что существенный смысл сохраняется и требования этой спецификации выполнены.

<a id="warnings"></a>
### Предупреждения

Предупреждение может быть выдано, когда система, по-видимому, удовлетворяет I18NSPEC, но содержит проблемы, которые должны быть задокументированы.

Предупреждения могут включать:

* небольшой непереведенный несущественный контент
* непоследовательную терминологию между locale
* несовершенные, но понятные переводы
* приемлемую эквивалентность locale, которую следует задокументировать
* ограниченное fallback-поведение
* частично переведенные необязательные страницы
* проблемы layout, чувствительного к направлению, которые не мешают существенному использованию
* значения, чувствительные к locale, которые понятны, но не идеальны

Предупреждения не обязательно препятствуют проверке.

<a id="failures"></a>
### Ошибки соответствия

Ошибка соответствия возникает, когда система не удовлетворяет одному или нескольким обязательным условиям I18NSPEC.

Ошибки соответствия могут включать:

* отсутствие поддержки требуемого locale
* существенное покрытие переводом на уровне 75% или ниже для требуемого locale
* непереведенный критический пользовательский контент
* отсутствие разумного механизма выбора языка
* выбор языка, требующий изменения исходного кода
* выбор языка, требующий инструментов разработчика
* сломанную загрузку переводов
* вводящие в заблуждение заявления о locale
* чрезмерное fallback-поведение
* fallback-контент, засчитанный как переведенный контент без действительной эквивалентности locale
* контент, чувствительный к направлению, который нечитаем или непригоден к использованию
* существенные рабочие процессы, недоступные в одном или нескольких требуемых locale

Ошибки соответствия препятствуют проверке, пока они не будут устранены.

<a id="verification-validity"></a>
### Действительность проверки

Проверка I18NSPEC применяется только к рассмотренному состоянию системы на момент выдачи проверки.

Система может сохранять проверку при последующих обновлениях, если она сохраняет проверенную основу интернационализации.

Небольшие изменения формулировок, добавленные переводы, улучшенные переводы и обычные обновления контента не аннулируют проверку автоматически.

Новый review может потребоваться, если система:

* удаляет поддержку требуемых locale
* ломает выбор языка
* существенно сокращает существенное покрытие переводом
* оставляет новые существенные рабочие процессы непереведенными
* заменяет переведенный контент fallback-контентом
* изменяет свою архитектуру перевода способом, который влияет на проверенное поведение
* вводит крупные пользовательские изменения, изменяющие рассмотренную область

Иными словами, улучшение поддержки перевода обычно приемлемо.

Поломка проверенной многоязычной основы может потребовать review.
