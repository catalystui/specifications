<a id="introduction"></a>
## 소개

**Internationalization Specification (I18NSPEC)** 는 CatalystUI 생태계 안에서 다국어 지원을 평가하는 데 사용되는 핵심 개념, 용어 및 요구 사항을 정합니다. 이 문서의 목적은 시스템, 서비스, 프레임워크, 애플리케이션 또는 구현이 명세 범위 안에 있다고 볼 수 있을 만큼 충분한 언어 지원을 제공하는지 판단하기 위한 명확한 기준을 제공하는 것입니다.

국제화가 중요한 이유는 사용자 인터페이스의 핵심 의미가 한 언어로만 제공될 경우 명확하게 소통할 수 없기 때문입니다. 시스템이 기술적으로는 동작하더라도 사용자가 레이블, 지침, 컨트롤, 설정, 경고, 오류 또는 핵심 워크플로를 이해할 수 없다면, 그 시스템은 해당 사용자에게 의미 있는 인터페이스를 제공하지 못한 것입니다.

이 명세는 완벽한 번역 품질, 문학적 문체, 문화적 적응, 법적 준수 또는 완전한 지역별 현지화를 측정하려는 것이 아닙니다. 대신 필수 CatalystUI 로케일 세트 전반에서 사용자가 시스템의 핵심 부분에 의미 있게 접근하고 이를 운용하는 데 필요한 최소한의 다국어 기반을 정의합니다.

더 쉽게 말하면, I18NSPEC 은 세 가지 주요 질문을 던집니다.

1. 사용자가 각 필수 언어로 시스템의 핵심 부분에 접근할 수 있는가?
2. 사용자가 자신이 이해하는 언어를 합리적으로 선택할 수 있는가?
3. 시스템이 언어 간에 충분한 의미를 보존하여 계속 사용할 수 있는 상태를 유지하는가?

> [!IMPORTANT]
>
> I18NSPEC 은 검증을 위한 국제화 요구 사항을 정의합니다. 각 언어마다 별도의 명세를 제공하는 것이 아닙니다. 각 필수 로케일은 동일한 명세에 따라 확인됩니다.

<a id="conformance"></a>
## 적합성

시스템은 필수 로케일 세트의 각 로케일에 대해 이 문서에서 정의한 요구 사항을 만족할 때 I18NSPEC 에 적합한 것으로 간주됩니다.

적합한 시스템은 다음을 충족해야 합니다.

1. 필수 로케일 세트의 각 로케일을 지원해야 합니다.
2. 각 필수 로케일에서 핵심 사용자 대상 콘텐츠의 75%를 초과하는 번역 콘텐츠를 제공해야 합니다.
3. 각 필수 로케일에서 모든 중요 사용자 대상 콘텐츠의 번역 콘텐츠를 제공해야 합니다.
4. 최종 사용자가 활성 로케일을 선택할 수 있는 합리적인 메커니즘을 제공해야 합니다.
5. 시스템에 적합한 안정적인 번역 메커니즘을 사용해야 합니다.
6. 번역된 사용자 대상 콘텐츠의 핵심 의미를 보존해야 합니다.
7. 검토 중 로케일 동등성이 인정되는 경우를 제외하고, 번역 범위를 주장하기 위해 대체 콘텐츠에 의존하지 않아야 합니다.

시스템은 이 명세에 적합하기 위해 하나의 특정 구현 패턴을 사용할 필요가 없습니다. 리소스 파일, 번역 테이블, 로케일 인식 라우팅, 컴파일된 언어 리소스, 정적 현지화 페이지, 런타임 언어 팩, 데이터베이스 기반 번역 또는 시스템에 적합한 다른 안정적인 메커니즘을 사용할 수 있습니다.

검증은 하나의 엄격한 기술 아키텍처가 아니라, 실제 사용자 접근성과 핵심 의미에 관심을 둡니다.

<a id="user-facing-content"></a>
## 사용자 대상 콘텐츠

<a id="user-facing-content-1"></a>
### 사용자 대상 콘텐츠

사용자 대상 콘텐츠란 최종 사용자가 지각하거나, 읽거나, 듣거나, 선택하거나, 이해하거나, 그에 따라 행동하도록 의도된 모든 콘텐츠입니다.

사용자 대상 콘텐츠에는 다음이 포함될 수 있습니다.

* 탐색
* 레이블
* 버튼
* 메뉴
* 컨트롤
* 제목
* 대화 상자
* 설정
* 지침
* 프롬프트
* 경고
* 오류
* 확인
* 상태 메시지
* 온보딩 텍스트
* 필수 도움말 텍스트
* 언어 선택 컨트롤
* 핵심 워크플로 콘텐츠

사용자 대상 콘텐츠가 반드시 시각적일 필요는 없습니다. 해당 콘텐츠가 사용자에게 의미를 전달한다면 청각, 촉각, 상징적 또는 다감각 콘텐츠도 포함될 수 있습니다.

<a id="essential-user-facing-content"></a>
### 핵심 사용자 대상 콘텐츠

핵심 사용자 대상 콘텐츠란 사용자가 시스템의 핵심 동작을 이해하고, 탐색하고, 구성하고, 운용하기 위해 합리적으로 필요로 하는 사용자 대상 콘텐츠입니다.

핵심 사용자 대상 콘텐츠에는 다음이 포함될 수 있습니다.

* 기본 탐색
* 핵심 화면과 보기
* 설정과 환경 설정
* 사용자 대상 레이블
* 사용자 대상 컨트롤
* 필수 지침
* 중요한 경고
* 중요한 오류
* 핵심 프롬프트
* 필수 확인 메시지
* 언어 선택 컨트롤
* 일반적인 사용에 필요한 핵심 워크플로

시스템은 I18NSPEC 을 충족하기 위해 모든 선택적 페이지, 숨겨진 메시지, 내부 레이블 또는 비핵심 텍스트를 번역할 필요는 없습니다. 그러나 일반적인 핵심 사용에 필요한 콘텐츠는 이 명세의 요구 사항에 따라 번역되어야 합니다.

<a id="critical-user-facing-content"></a>
### 중요 사용자 대상 콘텐츠

중요 사용자 대상 콘텐츠란 오해가 의미 있는 사용을 막거나, 심각한 오류를 만들거나, 사용자가 결과를 이해하지 못한 채 중요한 결정을 내리게 할 수 있는 핵심 사용자 대상 콘텐츠입니다.

중요 사용자 대상 콘텐츠에는 다음이 포함될 수 있습니다.

* 언어 선택 컨트롤
* 파괴적 작업 경고
* 계정 삭제 경고
* 결제 확인
* 구매 확인
* 개인정보 선택
* 보안 경고
* 동의 프롬프트
* 필수 안전 지침
* 필수 설정 지침
* 필수 오류 메시지
* 언어 설정에 도달하는 데 필요한 핵심 탐색

중요 사용자 대상 콘텐츠는 각 필수 로케일에 대해 번역되어야 합니다.

75% 핵심 번역 범위 기준을 사용해 중요 콘텐츠를 번역하지 않은 상태로 남겨서는 안 됩니다.

<a id="nonessential-content"></a>
### 비핵심 콘텐츠

비핵심 콘텐츠란 사용자가 시스템의 핵심 동작을 이해하고, 탐색하고, 구성하고, 운용하는 데 합리적으로 필요하지 않은 콘텐츠입니다.

비핵심 콘텐츠에는 다음이 포함될 수 있습니다.

* 내부 식별자
* 소스 코드 이름
* 디버그 전용 문자열
* 개발자 대상 구현 세부 정보
* 숨겨진 진단 텍스트
* 선택적 마케팅 페이지
* 선택적 지원 페이지
* 검토 범위 밖의 비핵심 법률 또는 비즈니스 텍스트
* 검토 대상 시스템이 제어하지 않는 타사 콘텐츠

비핵심 콘텐츠는 번역될 수 있지만, 핵심 사용자 이해나 운용에 필요해지지 않는 한 I18NSPEC 적합성에는 필수 사항이 아닙니다.

<a id="translation-coverage"></a>
## 번역 범위

<a id="essential-translation-coverage"></a>
### 핵심 번역 범위

핵심 번역 범위는 특정 로케일에 대해 번역된 핵심 사용자 대상 콘텐츠의 양입니다.

범위는 파일 크기, 바이트 수, 줄 수, 저장소 크기 또는 페이지 수가 아니라 의미 있는 사용자 대상 콘텐츠 단위로 평가되어야 합니다.

예를 들어, 핵심 작업을 제어하는 번역되지 않은 버튼 하나가 일반적인 사용에 영향을 주지 않는 긴 선택적 문단 하나보다 더 중요할 수 있습니다.

번역 범위는 검토 대상 로케일에서 사용자가 핵심 시스템을 의미 있게 이해하고 운용할 수 있는지에 따라 판단되어야 합니다.

<a id="coverage-requirement"></a>
### 범위 요구 사항

시스템은 특정 로케일에 대해 핵심 사용자 대상 콘텐츠의 75%를 초과하는 부분이 해당 로케일로 번역되어 있을 때 그 로케일의 번역 범위 요구 사항을 만족합니다.

시스템은 필수 로케일 세트의 모든 로케일에서 이 기준을 충족할 때 I18NSPEC 범위 요구 사항을 만족합니다.

실제 검토에서는 다음과 같이 나타낼 수 있습니다.

| 로케일  | 핵심 번역 범위 | 결과 |
| ------- | -------------- | ---- |
| `en-US` | 100%           | 통과 |
| `es-ES` | 94%            | 통과 |
| `ar-SA` | 78%            | 통과 |
| `ja-JP` | 61%            | 실패 |

범위가 75% 이하인 로케일은 범위 요구 사항을 만족하지 않습니다.

범위가 75%를 초과하는 로케일도 중요 사용자 대상 콘텐츠가 번역되지 않은 경우 실패할 수 있습니다.

<a id="critical-content-requirement"></a>
### 중요 콘텐츠 요구 사항

모든 중요 사용자 대상 콘텐츠는 각 필수 로케일에 대해 번역되어야 합니다.

일반 범위 기준을 충족하더라도 하나 이상의 중요 사용자 대상 콘텐츠 항목이 누락되었거나, 번역되지 않았거나, 오해를 불러일으키거나, 의미 있게 이해할 수 없다면 시스템은 I18NSPEC 에 실패할 수 있습니다.

예를 들어 일반 인터페이스는 번역되어 있지만 계정 삭제 경고, 구매 확인, 보안 경고 또는 언어 선택기가 번역되지 않은 상태라면 그 시스템은 명세 범위 안에 있다고 보아서는 안 됩니다.

<a id="language-selection"></a>
## 언어 선택

<a id="active-locale"></a>
### 활성 로케일

활성 로케일은 사용자 경험을 위해 현재 선택된 로케일입니다.

활성 로케일은 어떤 번역 콘텐츠가 사용자에게 표시, 제공 또는 다른 방식으로 전달되어야 하는지 결정합니다.

<a id="default-locale"></a>
### 기본 로케일

기본 로케일은 사용자가 활성 로케일을 선택하지 않았거나 사용자 선호를 사용할 수 없을 때 사용되는 로케일입니다.

시스템은 기본 로케일을 정의해야 합니다.

기본 로케일은 문서화되어 있거나 검토자가 합리적으로 추론할 수 있어야 합니다.

<a id="language-selection-mechanism"></a>
### 언어 선택 메커니즘

적합한 시스템은 최종 사용자가 활성 로케일을 변경할 수 있는 합리적인 방법을 제공해야 합니다.

언어 선택 메커니즘은 사용자가 다음을 요구받지 않고 사용할 수 있어야 합니다.

* 소스 코드 수정
* 개발자 도구 사용
* 문서화되지 않은 구성 파일 편집
* 비공식 패치 설치
* 숨겨진 동작에 의존
* 일반적인 언어 변경을 위해 지원팀에 연락

언어 선택 메커니즘은 다음을 통해 제공될 수 있습니다.

* 애플리케이션 설정
* 계정 환경 설정
* 언어 선택기
* 시작 프롬프트
* 브라우저 설정
* 운영 체제 설정
* 장치 설정
* 그 밖의 적절한 최종 사용자 접근 가능 메커니즘

메커니즘은 하나의 특정 디자인 패턴을 따를 필요가 없습니다. 사용자가 지원되는 언어를 합리적으로 선택할 수 있게 해야 합니다.

<a id="language-option-labels"></a>
### 언어 옵션 레이블

언어 옵션을 표시할 때 시스템은 해당 언어를 말하는 사용자가 이해할 수 있는 방식으로 각 언어를 식별해야 합니다.

언어 옵션에는 다음이 포함될 수 있습니다.

* 그 언어로 된 언어 이름
* 현재 활성 언어로 된 언어 이름
* 로케일 코드
* 지역 레이블
* 문자 레이블

예:

```md
English (English) (en-US)
Español (Spanish) (es-ES)
Français (French) (fr-FR)
العربية (Arabic) (ar-SA)
```

정확한 형식은 달라질 수 있습니다.

의도는 사용자가 자신의 언어를 알아볼 수 있고, 가능하다면 현재 표시된 언어 이름을 이해할 수 있으며, 관련 로케일 코드를 식별할 수 있도록 하는 것입니다.

<a id="fallbacks-and-locale-equivalence"></a>
## 대체 처리와 로케일 동등성

<a id="fallback-locale"></a>
### 대체 로케일

대체 로케일은 활성 로케일에 대한 번역 콘텐츠를 사용할 수 없을 때 사용되는 로케일입니다.

대체 로케일은 사용성을 보존하는 데 도움이 될 수 있지만, 대체 콘텐츠가 자동으로 활성 로케일을 위한 번역 콘텐츠로 간주되지는 않습니다.

예를 들어 시스템이 `es-MX` 로 설정되어 있지만 스페인어 번역이 누락되어 `en-US` 텍스트를 표시한다면, 그 영어 텍스트는 대체 콘텐츠로 유용할 수는 있지만 스페인어 번역 범위로 계산되어서는 안 됩니다.

<a id="fallback-behavior"></a>
### 대체 동작

적합한 시스템은 현지화된 콘텐츠를 사용할 수 없을 때 대체 동작을 사용할 수 있습니다.

대체 동작은 깨진 출력, 빈 출력 또는 오해를 불러일으키는 출력을 피해야 합니다.

대체 동작을 필수 로케일의 번역 범위를 거짓으로 주장하는 데 사용해서는 안 됩니다.

대체 동작이 과도하거나, 혼란스럽거나, 문서화되지 않았거나, 필수 로케일에서 핵심 콘텐츠가 번역되지 않은 것처럼 보이게 만든다면 시스템은 경고 또는 실패를 받을 수 있습니다.

<a id="locale-equivalence"></a>
### 로케일 동등성

로케일 동등성은 하나의 번역이 핵심 이해나 운용을 방해하지 않고 둘 이상의 로케일에 합리적으로 사용될 수 있는 경우를 말합니다.

예를 들어 핵심 의미가 각 로케일의 사용자에게 명확하게 유지된다면 시스템은 `en-US`, `en-GB`, `en-IN` 에 하나의 영어 번역을 사용할 수 있습니다.

지역 차이가 작고 핵심 사용성에 실질적인 영향을 주지 않는 경우, 검토 중 로케일 동등성이 인정될 수 있습니다.

누락된 로케일이 의미 있는 혼란을 만들거나, 중요한 지역 용어를 생략하거나, 핵심 동작을 깨뜨리거나, 사용자가 시스템을 이해하지 못하게 한다면 로케일 동등성을 사용해서는 안 됩니다.

예를 들어 관련 없는 언어들이 쓰기 방향, 지리적 지역, 문자 계열 또는 넓은 문화 범주를 공유한다는 이유만으로 동등하다고 가정해서는 안 됩니다.

로케일 동등성은 검토 판단이며 자동 규칙이 아닙니다.

<a id="implementation-requirements"></a>
## 구현 요구 사항

<a id="stable-translation-mechanism"></a>
### 안정적인 번역 메커니즘

적합한 시스템은 검토 대상 시스템에 적합한 안정적인 번역 메커니즘을 사용해야 합니다.

안정적인 번역 메커니즘은 취약하거나 문서화되지 않은 동작에 의존하지 않고 번역 콘텐츠를 유지 관리, 업데이트, 검토 및 확장할 수 있게 해야 합니다.

안정적인 번역 메커니즘에는 다음이 포함될 수 있습니다.

* 리소스 파일
* 번역 테이블
* 로케일 인식 라우팅
* 컴파일된 언어 자산
* 정적 현지화 페이지
* 런타임 언어 팩
* 데이터베이스 기반 번역
* 그 밖의 문서화된 번역 구조

시스템은 필수 번역 지원을 방해하는 방식으로 핵심 사용자 대상 콘텐츠를 하드코딩하는 일을 피해야 합니다.

<a id="preservation-of-meaning"></a>
### 의미 보존

번역이 의미를 보존한다는 것은 사용자가 원문 언어 사용자와 동일한 핵심 지침, 레이블, 경고, 컨트롤, 설정 또는 워크플로를 합리적으로 이해할 수 있음을 의미합니다.

번역은 원문 콘텐츠와 단어 대 단어로 동일할 필요가 없습니다.

대상 언어에서 동일한 핵심 의미를 전달하기 위해 필요하다면 번역은 어순, 문법, 문장 구조, 관용 표현, 어조 또는 표현 방식을 변경할 수 있습니다.

번역이 오해를 불러일으키거나, 불완전하거나, 의미가 없거나, 기계적으로 손상되었거나, 핵심 사용에 영향을 주는 방식으로 원문과 의미가 다르다면 검토에 실패할 수 있습니다.

<a id="direction-sensitive-languages"></a>
### 방향에 민감한 언어

일부 필수 로케일은 일반적으로 오른쪽에서 왼쪽으로 쓰는 텍스트 방향을 사용합니다.

적합한 시스템은 활성 로케일이 다른 텍스트 방향을 사용한다는 이유로 핵심 번역 콘텐츠를 읽거나, 이해하거나, 선택하거나, 조작할 수 없게 해서는 안 됩니다.

시스템은 방향에 민감한 언어에 대해 읽기 쉬운 순서, 문장 부호 동작, 컨트롤 연결을 보존해야 합니다.

완전한 시각적 다듬기, 타이포그래피 품질, 접근성 동작 및 레이아웃 개선은 별도 검토가 필요할 수 있습니다. 그러나 핵심 번역 콘텐츠는 의미 있게 사용할 수 있는 상태로 남아 있어야 합니다.

<a id="locale-sensitive-values"></a>
### 로케일에 민감한 값

로케일에 민감한 값은 의미나 가독성이 언어, 지역, 문자 또는 문화에 따라 달라질 수 있는 값입니다.

로케일에 민감한 값에는 다음이 포함될 수 있습니다.

* 날짜
* 시간
* 숫자
* 통화
* 측정 단위
* 복수형
* 문법적 성
* 정렬 순서
* 주소 형식
* 전화번호 형식

I18NSPEC 은 해당 값이 시스템을 이해하거나 운용하는 데 핵심적이지 않은 한 모든 로케일에 민감한 값의 완전한 현지화를 요구하지 않습니다.

로케일에 민감한 값이 핵심적인 경우, 시스템은 활성 로케일의 사용자가 합리적으로 이해할 수 있는 방식으로 이를 표현해야 합니다.

<a id="verification"></a>
## 검증

<a id="within-spec"></a>
### 명세 범위 안

CatalystUI Team 이 시스템을 검토하고 I18NSPEC 을 만족한다고 합리적으로 결론 내릴 수 있을 때, 그 시스템은 명세 범위 안에 있는 것으로 간주됩니다.

시스템은 다음과 같은 경우 명세 범위 안에 있을 수 있습니다.

* 모든 필수 로케일이 지원됨
* 각 필수 로케일에서 핵심 사용자 대상 콘텐츠의 75%를 초과하는 부분이 번역됨
* 각 필수 로케일에서 모든 중요 사용자 대상 콘텐츠가 번역됨
* 사용자가 활성 로케일을 합리적으로 선택할 수 있음
* 대체 동작이 번역 범위를 거짓으로 주장하지 않음
* 로케일 동등성을 사용하는 경우 그것이 합리적이고 문서화되어 있음
* 번역 콘텐츠가 핵심 의미를 보존함

일부 비핵심 콘텐츠가 번역되지 않은 상태로 남아 있어도 시스템은 명세 범위 안에 있을 수 있습니다.

번역이 완벽하지 않더라도 핵심 의미가 보존되고 이 명세의 요구 사항이 충족된다면 시스템은 명세 범위 안에 있을 수 있습니다.

<a id="warnings"></a>
### 경고

시스템이 I18NSPEC 을 만족하는 것처럼 보이지만 문서화해야 할 우려가 있을 때 경고가 발행될 수 있습니다.

경고에는 다음이 포함될 수 있습니다.

* 사소한 번역되지 않은 비핵심 콘텐츠
* 로케일 간 일관되지 않은 용어
* 완벽하지 않지만 이해 가능한 번역
* 문서화되어야 하는 허용 가능한 로케일 동등성
* 제한적인 대체 동작
* 일부만 번역된 선택적 페이지
* 핵심 사용을 막지는 않는 방향 민감 레이아웃 우려
* 이해 가능하지만 이상적이지 않은 로케일 민감 값

경고가 반드시 검증을 막는 것은 아닙니다.

<a id="failures"></a>
### 실패

실패는 시스템이 I18NSPEC 의 하나 이상의 필수 조건을 만족하지 못할 때 발생합니다.

실패에는 다음이 포함될 수 있습니다.

* 필수 로케일 지원 누락
* 필수 로케일의 핵심 번역 범위가 75% 이하
* 번역되지 않은 중요 사용자 대상 콘텐츠
* 합리적인 언어 선택 메커니즘 없음
* 언어 선택에 소스 코드 수정 필요
* 언어 선택에 개발자 도구 필요
* 번역 로딩 손상
* 오해를 불러일으키는 로케일 주장
* 과도한 대체 동작
* 유효한 로케일 동등성 없이 대체 콘텐츠를 번역 콘텐츠로 계산함
* 방향에 민감한 콘텐츠를 읽거나 사용할 수 없음
* 하나 이상의 필수 로케일에서 핵심 워크플로를 사용할 수 없음

실패는 해결될 때까지 검증을 막습니다.

<a id="verification-validity"></a>
### 검증 유효성

I18NSPEC 검증은 검증이 발행된 시점에 검토된 시스템 상태에만 적용됩니다.

시스템은 검증된 국제화 기반을 보존하는 한 이후 업데이트에서도 검증을 유지할 수 있습니다.

사소한 문구 변경, 추가 번역, 개선된 번역 및 일반적인 콘텐츠 업데이트는 자동으로 검증을 무효화하지 않습니다.

다음과 같은 경우 새 검토가 필요할 수 있습니다.

* 필수 로케일 지원 제거
* 언어 선택 파손
* 핵심 번역 범위의 실질적 감소
* 새로운 핵심 워크플로를 번역하지 않은 상태로 둠
* 번역 콘텐츠를 대체 콘텐츠로 교체
* 검증된 동작에 영향을 주는 방식으로 번역 아키텍처 변경
* 검토 범위를 바꾸는 주요 사용자 대상 변경 도입

다시 말해, 번역 지원을 개선하는 것은 보통 문제가 없습니다.

검증된 다국어 기반을 깨뜨리는 경우 검토가 필요할 수 있습니다.
