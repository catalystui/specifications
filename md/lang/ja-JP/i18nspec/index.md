<a id="introduction"></a>
## はじめに

**Internationalization Specification (I18NSPEC)** は、CatalystUI エコシステム内で多言語サポートを評価するために使用される中核的な概念、用語、および要件を定めます。その目的は、システム、サービス、フレームワーク、アプリケーション、または実装が、仕様内と見なされるために十分な言語サポートを提供しているかどうかを判断するための明確な標準を提供することです。

国際化が重要なのは、ユーザーインターフェイスの本質的な意味が一つの言語でしか利用できない場合、そのインターフェイスは明確に伝達できないからです。システムが技術的には機能していても、ユーザーがラベル、手順、コントロール、設定、警告、エラー、または主要なワークフローを理解できないなら、そのシステムはそのユーザーにとって意味のあるインターフェイスを提供できていません。

この仕様は、完全な翻訳品質、文学的な文体、文化的適応、法的準拠、または完全な地域ローカライゼーションを測定しようとするものではありません。代わりに、必要な CatalystUI ロケールセット全体で、ユーザーがシステムの本質的な部分に意味をもってアクセスし操作できるために必要な、最小限の多言語基盤を定義します。

より簡単に言えば、I18NSPEC は主に三つの質問をします。

1. ユーザーは各必須言語でシステムの本質的な部分にアクセスできるか。
2. ユーザーは自分が理解できる言語を合理的に選択できるか。
3. システムは、使いやすさを保てるだけの意味を言語間で十分に保持しているか。

> [!IMPORTANT]
>
> I18NSPEC は検証のための国際化要件を定義します。これは各言語ごとの別個の仕様ではありません。各必須ロケールは、同じ仕様に照らして確認されます。

<a id="conformance"></a>
## 適合性

システムは、必須ロケールセット内の各ロケールについて、この文書で定義された要件を満たす場合、I18NSPEC に適合していると見なされます。

適合するシステムは、次を満たさなければなりません。

1. 必須ロケールセット内の各ロケールをサポートすること。
2. 各必須ロケールで、本質的なユーザー向けコンテンツの 75% を超える翻訳済みコンテンツを提供すること。
3. 各必須ロケールで、すべての重要なユーザー向けコンテンツの翻訳済みコンテンツを提供すること。
4. エンドユーザーがアクティブロケールを選択するための合理的なメカニズムを提供すること。
5. システムに適した安定した翻訳メカニズムを使用すること。
6. 翻訳されたユーザー向けコンテンツの本質的な意味を保持すること。
7. ロケール同等性がレビューで認められる場合を除き、翻訳カバレッジを主張するためにフォールバックコンテンツへ依存しないこと。

この仕様に適合するために、システムが特定の実装パターンを一つだけ使用する必要はありません。リソースファイル、翻訳テーブル、ロケール対応ルーティング、コンパイル済み言語リソース、静的なローカライズページ、実行時の言語パック、データベースに基づく翻訳、またはシステムに適した別の安定したメカニズムを使用できます。

検証が重視するのは、実用的なユーザーアクセスと本質的な意味であり、硬直した一つの技術アーキテクチャではありません。

<a id="user-facing-content"></a>
## ユーザー向けコンテンツ

<a id="user-facing-content-1"></a>
### ユーザー向けコンテンツ

ユーザー向けコンテンツとは、エンドユーザーが知覚し、読み、聞き、選択し、理解し、またはそれに基づいて行動することを意図したあらゆるコンテンツです。

ユーザー向けコンテンツには、次のものが含まれる場合があります。

* ナビゲーション
* ラベル
* ボタン
* メニュー
* コントロール
* 見出し
* ダイアログ
* 設定
* 手順
* プロンプト
* 警告
* エラー
* 確認
* ステータスメッセージ
* オンボーディングテキスト
* 必須ヘルプテキスト
* 言語選択コントロール
* 主要ワークフローのコンテンツ

ユーザー向けコンテンツは視覚的である必要はありません。そのコンテンツがユーザーに意味を伝える場合、聴覚的、触覚的、記号的、またはマルチセンサリーなコンテンツも含まれることがあります。

<a id="essential-user-facing-content"></a>
### 本質的なユーザー向けコンテンツ

本質的なユーザー向けコンテンツとは、ユーザーがシステムの本質的な動作を理解し、移動し、設定し、操作するために合理的に必要とするユーザー向けコンテンツです。

本質的なユーザー向けコンテンツには、次のものが含まれる場合があります。

* 主要ナビゲーション
* 主要な画面とビュー
* 設定と環境設定
* ユーザー向けラベル
* ユーザー向けコントロール
* 必須の手順
* 重要な警告
* 重要なエラー
* 本質的なプロンプト
* 必須の確認メッセージ
* 言語選択コントロール
* 通常利用に必要な主要ワークフロー

システムは、I18NSPEC を満たすために、すべての任意ページ、非表示メッセージ、内部ラベル、または非本質的なテキストを翻訳する必要はありません。ただし、通常の本質的な使用に必要なコンテンツは、この仕様の要件に従って翻訳されなければなりません。

<a id="critical-user-facing-content"></a>
### 重要なユーザー向けコンテンツ

重要なユーザー向けコンテンツとは、誤解によって意味のある使用が妨げられたり、重大なエラーが発生したり、ユーザーが結果を理解しないまま重要な決定を下したりする可能性がある、本質的なユーザー向けコンテンツです。

重要なユーザー向けコンテンツには、次のものが含まれる場合があります。

* 言語選択コントロール
* 破壊的操作の警告
* アカウント削除の警告
* 支払い確認
* 購入確認
* プライバシー選択
* セキュリティ警告
* 同意プロンプト
* 必須の安全手順
* 必須のセットアップ手順
* 必須のエラーメッセージ
* 言語設定に到達するために必要な主要ナビゲーション

重要なユーザー向けコンテンツは、各必須ロケールで翻訳されなければなりません。

75% の本質的翻訳カバレッジしきい値を、重要コンテンツを未翻訳のままにするために使用してはなりません。

<a id="nonessential-content"></a>
### 非本質的コンテンツ

非本質的コンテンツとは、ユーザーがシステムの本質的な動作を理解し、移動し、設定し、操作するために合理的に必要ではないコンテンツです。

非本質的コンテンツには、次のものが含まれる場合があります。

* 内部識別子
* ソースコード名
* デバッグ専用文字列
* 開発者向け実装詳細
* 非表示の診断テキスト
* 任意のマーケティングページ
* 任意のサポートページ
* レビュー範囲外の非本質的な法務またはビジネステキスト
* レビュー対象システムが管理していない第三者コンテンツ

非本質的コンテンツは翻訳されてもかまいませんが、本質的なユーザー理解または操作に必要にならない限り、I18NSPEC 適合のためには必須ではありません。

<a id="translation-coverage"></a>
## 翻訳カバレッジ

<a id="essential-translation-coverage"></a>
### 本質的な翻訳カバレッジ

本質的な翻訳カバレッジとは、特定のロケール向けに翻訳された本質的なユーザー向けコンテンツの量です。

カバレッジは、ファイルサイズ、バイト数、行数、リポジトリサイズ、またはページ数ではなく、意味のあるユーザー向けコンテンツ単位によって評価されるべきです。

たとえば、本質的な操作を制御する未翻訳のボタン一つは、通常利用に影響しない大きな任意段落が未翻訳であることより重要な場合があります。

翻訳カバレッジは、レビュー対象ロケールでユーザーが本質的なシステムを意味をもって理解し操作できるかどうかによって判断されるべきです。

<a id="coverage-requirement"></a>
### カバレッジ要件

システムは、あるロケールについて本質的なユーザー向けコンテンツの 75% を超える部分がそのロケールに翻訳されている場合、そのロケールの翻訳カバレッジ要件を満たします。

システムは、必須ロケールセット内のすべてのロケールでこのしきい値を満たす場合、I18NSPEC カバレッジ要件を満たします。

実際のレビューでは、次のように表せます。

| ロケール | 本質的翻訳カバレッジ | 結果 |
| ------- | -------------------- | ---- |
| `en-US` | 100%                 | 合格 |
| `es-ES` | 94%                  | 合格 |
| `ar-SA` | 78%                  | 合格 |
| `ja-JP` | 61%                  | 不合格 |

カバレッジが 75% 以下のロケールは、カバレッジ要件を満たしません。

カバレッジが 75% を超えるロケールでも、重要なユーザー向けコンテンツが未翻訳であれば失敗する場合があります。

<a id="critical-content-requirement"></a>
### 重要コンテンツ要件

すべての重要なユーザー向けコンテンツは、各必須ロケールで翻訳されなければなりません。

一般的なカバレッジしきい値を満たしている場合でも、一つ以上の重要なユーザー向けコンテンツ項目が欠落している、未翻訳である、誤解を招く、または意味をもって理解できない場合、システムは I18NSPEC に失敗することがあります。

たとえば、一般的なインターフェイスが翻訳されていても、アカウント削除警告、購入確認、セキュリティ警告、または言語セレクターが未翻訳のままであれば、そのシステムを仕様内と見なすべきではありません。

<a id="language-selection"></a>
## 言語選択

<a id="active-locale"></a>
### アクティブロケール

アクティブロケールとは、ユーザーの体験のために現在選択されているロケールです。

アクティブロケールは、どの翻訳済みコンテンツをユーザーに表示、提供、またはその他の方法で伝達すべきかを決定します。

<a id="default-locale"></a>
### デフォルトロケール

デフォルトロケールとは、ユーザーがアクティブロケールを選択していない場合、またはユーザー設定が利用できない場合に使用されるロケールです。

システムはデフォルトロケールを定義しなければなりません。

デフォルトロケールは、文書化されているか、レビュー担当者が合理的に推測できるべきです。

<a id="language-selection-mechanism"></a>
### 言語選択メカニズム

適合するシステムは、エンドユーザーがアクティブロケールを変更するための合理的な方法を提供しなければなりません。

言語選択メカニズムは、ユーザーに次のことを要求せずに利用できなければなりません。

* ソースコードを変更する
* 開発者ツールを使用する
* 文書化されていない設定ファイルを編集する
* 非公式パッチをインストールする
* 隠れた動作に依存する
* 通常の言語変更のためにサポートへ連絡する

言語選択メカニズムは、次のような方法で提供できます。

* アプリケーション設定
* アカウント設定
* 言語セレクター
* 起動時プロンプト
* ブラウザー設定
* オペレーティングシステム設定
* デバイス設定
* その他の適切な、エンドユーザーがアクセスできるメカニズム

メカニズムは特定のデザインパターンに従う必要はありません。ユーザーがサポートされている言語を合理的に選択できなければなりません。

<a id="language-option-labels"></a>
### 言語オプションのラベル

言語オプションを表示するとき、システムは、その言語を話すユーザーに理解できる方法で各言語を識別すべきです。

言語オプションには、次のものを含めることができます。

* その言語での言語名
* 現在のアクティブ言語での言語名
* ロケールコード
* 地域ラベル
* 文字体系ラベル

例:

```md
English (English) (en-US)
Español (Spanish) (es-ES)
Français (French) (fr-FR)
العربية (Arabic) (ar-SA)
```

正確な形式は異なる場合があります。

意図しているのは、ユーザーが自分の言語を認識でき、可能な場合は現在表示されている言語名を理解でき、関連するロケールコードを識別できることです。

<a id="fallbacks-and-locale-equivalence"></a>
## フォールバックとロケール同等性

<a id="fallback-locale"></a>
### フォールバックロケール

フォールバックロケールとは、アクティブロケール向けの翻訳済みコンテンツが利用できない場合に使用されるロケールです。

フォールバックロケールは使いやすさを維持する助けになることがありますが、フォールバックコンテンツはアクティブロケール向けに翻訳されたコンテンツとは自動的には見なされません。

たとえば、システムが `es-MX` に設定されているのに、スペイン語翻訳が欠落しているため `en-US` のテキストを表示する場合、その英語テキストはフォールバックとして有用かもしれませんが、スペイン語翻訳カバレッジとして数えるべきではありません。

<a id="fallback-behavior"></a>
### フォールバック動作

適合するシステムは、ローカライズされたコンテンツが利用できない場合にフォールバック動作を使用できます。

フォールバック動作は、壊れた出力、空の出力、または誤解を招く出力を避けるべきです。

フォールバック動作を、必須ロケールの翻訳カバレッジを偽って主張するために使用してはなりません。

フォールバック動作が過剰、混乱を招く、文書化されていない、または必須ロケールで本質的コンテンツが未翻訳のように見える原因となる場合、システムは警告または失敗を受けることがあります。

<a id="locale-equivalence"></a>
### ロケール同等性

ロケール同等性とは、一つの翻訳が、複数のロケールに対して本質的な理解や操作を妨げることなく合理的に機能できる場合を指します。

たとえば、本質的な意味が各ロケールのユーザーにとって明確なままであれば、システムは `en-US`、`en-GB`、`en-IN` に対して一つの英語翻訳を使用できます。

地域差が小さく、本質的な使いやすさに実質的な影響を与えない場合、レビュー中にロケール同等性が認められることがあります。

欠落したロケールが意味のある混乱を生む、重要な地域用語を省く、本質的な動作を壊す、またはユーザーがシステムを理解することを妨げる場合、ロケール同等性を使用してはなりません。

たとえば、書字方向、地理的地域、文字体系ファミリー、または広い文化カテゴリを共有しているという理由だけで、無関係な言語が同等であると仮定すべきではありません。

ロケール同等性はレビュー判断であり、自動的な規則ではありません。

<a id="implementation-requirements"></a>
## 実装要件

<a id="stable-translation-mechanism"></a>
### 安定した翻訳メカニズム

適合するシステムは、レビュー対象のシステムに適した安定した翻訳メカニズムを使用しなければなりません。

安定した翻訳メカニズムは、脆弱または文書化されていない動作に依存することなく、翻訳済みコンテンツを保守、更新、レビュー、拡張できるようにすべきです。

安定した翻訳メカニズムには、次のものが含まれる場合があります。

* リソースファイル
* 翻訳テーブル
* ロケール対応ルーティング
* コンパイル済み言語アセット
* 静的なローカライズページ
* 実行時の言語パック
* データベースに基づく翻訳
* その他の文書化された翻訳構造

システムは、必須翻訳サポートを妨げる形で本質的なユーザー向けコンテンツをハードコードすることを避けるべきです。

<a id="preservation-of-meaning"></a>
### 意味の保持

翻訳が意味を保持しているとは、ユーザーがソース言語のユーザーと同じ本質的な指示、ラベル、警告、コントロール、設定、またはワークフローを合理的に理解できることを意味します。

翻訳は、ソースコンテンツと一語一句同一である必要はありません。

対象言語で同じ本質的な意味を伝えるために必要であれば、翻訳は語順、文法、文構造、慣用表現、口調、または表現を変更できます。

翻訳が誤解を招く、不完全、意味不明、機械的に破損している、または本質的な使用に影響する形でソースコンテンツと意味が異なる場合、レビューに失敗することがあります。

<a id="direction-sensitive-languages"></a>
### 方向に敏感な言語

一部の必須ロケールでは、一般的に右から左へのテキスト方向が使用されます。

適合するシステムは、アクティブロケールが異なるテキスト方向を使用するために、本質的な翻訳済みコンテンツを読めない、理解できない、選択できない、または操作できない状態にしてはなりません。

システムは、方向に敏感な言語について、読みやすい順序、句読点の動作、およびコントロールとの関連付けを保持すべきです。

完全な視覚的洗練、タイポグラフィ品質、アクセシビリティ動作、およびレイアウト調整には、別個のレビューが必要な場合があります。ただし、本質的な翻訳済みコンテンツは意味をもって使用できる状態でなければなりません。

<a id="locale-sensitive-values"></a>
### ロケールに敏感な値

ロケールに敏感な値とは、意味や読みやすさが言語、地域、文字体系、または文化によって変わる可能性がある値です。

ロケールに敏感な値には、次のものが含まれる場合があります。

* 日付
* 時刻
* 数値
* 通貨
* 測定単位
* 複数形
* 文法上の性
* ソート順
* 住所形式
* 電話番号形式

I18NSPEC は、値がシステムを理解または操作するために本質的でない限り、すべてのロケールに敏感な値の完全なローカライゼーションを要求しません。

ロケールに敏感な値が本質的である場合、システムはアクティブロケールのユーザーが合理的に理解できる方法でそれらを表現すべきです。

<a id="verification"></a>
## 検証

<a id="within-spec"></a>
### 仕様内

CatalystUI Team がシステムをレビューし、それが I18NSPEC を満たしていると合理的に結論づけられる場合、そのシステムは仕様内と見なされます。

システムは、次の場合に仕様内となることがあります。

* すべての必須ロケールがサポートされている
* 各必須ロケールで、本質的なユーザー向けコンテンツの 75% を超える部分が翻訳されている
* 各必須ロケールですべての重要なユーザー向けコンテンツが翻訳されている
* ユーザーがアクティブロケールを合理的に選択できる
* フォールバック動作が翻訳カバレッジを偽って主張していない
* ロケール同等性が使用される場合、それが合理的で文書化されている
* 翻訳済みコンテンツが本質的な意味を保持している

一部の非本質的コンテンツが未翻訳のままであっても、システムは仕様内となる場合があります。

翻訳が完全でなくても、本質的な意味が保持され、この仕様の要件が満たされていれば、システムは仕様内となる場合があります。

<a id="warnings"></a>
### 警告

警告は、システムが I18NSPEC を満たしているように見えるものの、文書化されるべき懸念がある場合に発行されることがあります。

警告には、次のものが含まれる場合があります。

* 軽微な未翻訳の非本質的コンテンツ
* ロケール間で一貫しない用語
* 完全ではないが理解可能な翻訳
* 文書化されるべき許容可能なロケール同等性
* 限定的なフォールバック動作
* 一部翻訳された任意ページ
* 本質的な使用を妨げない、方向に敏感なレイアウト上の懸念
* 理解はできるが理想的ではないロケールに敏感な値

警告は必ずしも検証を妨げるものではありません。

<a id="failures"></a>
### 失敗

失敗は、システムが I18NSPEC の一つ以上の必須条件を満たしていない場合に発生します。

失敗には、次のものが含まれる場合があります。

* 必須ロケールのサポート欠如
* 必須ロケールでの本質的翻訳カバレッジが 75% 以下
* 未翻訳の重要なユーザー向けコンテンツ
* 合理的な言語選択メカニズムがない
* 言語選択にソースコード変更が必要
* 言語選択に開発者ツールが必要
* 翻訳読み込みの破損
* 誤解を招くロケール主張
* 過剰なフォールバック動作
* 有効なロケール同等性なしに、フォールバックコンテンツを翻訳済みコンテンツとして数えている
* 方向に敏感なコンテンツが読めない、または使用できない
* 一つ以上の必須ロケールで本質的なワークフローが利用できない

失敗は、解決されるまで検証を妨げます。

<a id="verification-validity"></a>
### 検証の有効性

I18NSPEC 検証は、検証が発行された時点でレビューされたシステムの状態にのみ適用されます。

システムは、検証済みの国際化基盤を維持している限り、後の更新後も検証を保持できます。

軽微な文言変更、追加翻訳、改善された翻訳、および通常のコンテンツ更新は、自動的に検証を無効にしません。

次の場合、新しいレビューが必要になることがあります。

* 必須ロケールサポートを削除する
* 言語選択を壊す
* 本質的翻訳カバレッジを大幅に減らす
* 新しい本質的ワークフローを未翻訳のままにする
* 翻訳済みコンテンツをフォールバックコンテンツで置き換える
* 検証済み動作に影響する形で翻訳アーキテクチャを変更する
* レビュー範囲を変える主要なユーザー向け変更を導入する

言い換えれば、翻訳サポートを改善することは通常問題ありません。

検証済みの多言語基盤を壊す場合、レビューが必要になることがあります。
